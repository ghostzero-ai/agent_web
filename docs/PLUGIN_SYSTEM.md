# 第一方插件系统

Phase 7.1–7.3 已建立最小插件发现、生命周期、受控能力和首个真实活动。当前目标是继续用解题活动验证边界，不是开放第三方生态。

## 当前数据流

```text
仓库内第一方 Manifest
  → Zod 严格校验
  → Plugin API 版本范围检查
  → Registry 隔离无效或重复项
  → 与 PostgreSQL plugin_installations 合并
  → /api/v1/plugins
  → Web / Capacitor /plugins
  → 用户逐项授权
  → Capability Gateway 检查版本、上下文和配额
  → 已注册的宿主 Adapter
```

Manifest 是随应用构建的只读声明。数据库保存启停、授权、配额、隔离数据和审计，但不保存插件代码；修改数据库不能注入新的插件或注册新的 Adapter。

## 当前第一方插件

| ID | 名称 | 当前状态 | 完整活动阶段 |
|---|---|---|---|
| `study.memorization` | 背书训练 | 可用：导入、校对、复述、评分、间隔复习、任务草稿 | Phase 7.3 ✅ |
| `study.problem-solving` | 解题训练 | Manifest 与启停基础 | Phase 7.4 |

启用插件不会让尚未实现的活动伪装成可用功能，也不会自动授予任何能力。背书训练启用后可从 `/plugins` 进入 `/study/memorization`；解题训练仍只展示基础状态。

## 兼容规则

- Manifest Schema：`1`。
- 当前宿主 Plugin API：实验版 `0.1.0`。
- 第一方插件声明半开范围，例如 `>=0.1.0 <0.2.0`。
- 宿主版本不在范围内时，插件保持可发现但有效停用；启用请求返回稳定的 `PLUGIN_INCOMPATIBLE`。
- API 范围、Manifest 结构或重复 ID 无效时只隔离该项，不阻塞 Chat、Task、Inbox 或其他插件。

## 安全与能力边界

`requestedCapabilities` 只是 Manifest 声明，不是授权。用户必须在 `/plugins` 对每项能力单独授权；禁用插件会立即使全部授权无效，但仍允许用户撤销已保存授权。插件版本变化后旧授权进入待复核状态。

Capability Gateway 的每次调用依次检查：

1. 能力属于宿主白名单且被插件 Manifest 声明。
2. 插件兼容、已启用，安装版本与当前 Manifest 一致。
3. 用户授权存在，并且是在当前插件版本下审核。
4. 前台调用来自用户动作；后台调用具有明确 Run ID。
5. 当日用量没有超过能力目录中的固定上限。
6. 宿主已注册对应的结构化 Adapter。

插件不能取得 PostgreSQL 连接、任意 SQL、模型密钥、网络客户端或核心 Repository。当前注册三个宿主 Adapter：隔离 JSON 存储、仅接受背书评价结构的模型生成，以及只返回待确认提醒的任务草稿。解题所需的模型输入结构会在 7.4 扩充；没有面向浏览器的通用能力执行 API。

## 背书活动数据流

```text
材料 → 确定性拆分 → 用户校对 → 隔离存储
     → 隐藏原文复述 → 本地评分 + 可选模型评价
     → 薄弱点/间隔/学习记录 → 任务草稿
     → 用户再次确认 → 核心 Task API
```

模型拒绝、未配置或临时不可用不会丢失复习机会，活动会明确使用确定性评分。任务草稿能力被拒绝时只保存成绩，不创建提醒。

## 隔离存储与配额

- 隔离键由 `userId + pluginId + key` 确定，同名键不能跨插件读取。
- Key 只允许 1–120 个安全字符；值必须是 JSON。
- 单值最多 64 KiB；每插件最多 250 项、合计 1 MiB。
- 写入和删除使用乐观版本锁，避免多端静默覆盖。
- 配额按 UTC 自然日、用户、插件和能力分别计数；当前模型 40、存储 500、任务草稿 20 单位/日。

## 审计边界

授权变化、Gateway 拒绝、成功和 Adapter 失败均写入 `plugin_capability_audit`。记录只包含请求 ID、插件、能力、操作、前台/后台/授权上下文、Run ID、结果、错误码、用量和耗时。审计明确不保存 Prompt、学习材料、存储值、模型返回或 API Key。

第三方安装包、动态服务端/原生代码、插件市场、热重载、UI 沙箱与签名分发仍不在近期范围。当前第一方代码与宿主同进程，因此安全边界依赖静态注册、代码审查和 Gateway 依赖方向；这不等同于第三方代码沙箱。
