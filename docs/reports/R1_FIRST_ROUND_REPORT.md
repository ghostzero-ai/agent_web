## 1. 实现结果

1. 所有生产模型入口共用用量采集：聊天、任务、新闻、书籍、反思、学习及娱乐。解析输入/输出/缓存/推理 Token、延迟、请求尝试、成功/失败/取消及结束原因。缺失数据为未知，不是零；不记录 Key、Prompt、回答正文。
2. 新增 PostgreSQL `model_usage_calls` 和 0027 迁移；Web/APK 模型配置页可查看最近七天统计、缓存覆盖率与按货币分组的配置价格估算。价格不写死、不追溯修改历史。
3. 固定规则前置，日期/材料后置；游戏将变化状态移到已有历史之后。结构化上下文稳定紧凑序列化；检索保留发布日期和检索日，不重复传秒级抓取时间。所选分支、Persona、真实记忆和可信检定边界不改变。
4. 按业务配置输出上限；未知兼容端点默认不猜参数。调用前字符护栏明确拒绝超大输入但保留原始历史。长度截断和无完成标记的断流明确报错，不自动二次调用；退出流时取消上游读取。
5. 仅删除完全重复的联网证据，不合并不同材料。七个无网络结构样例可通过 `npm run eval:cost` 复现，真实 Token/缓存/费用字段为 null。

实现与配置规范见 `../TOKEN_COST_GUIDE.md`；规划状态已同步主线、总路线图与优化任务文档。没有新增 npm 依赖，也没有修改冻结的 Plugin API。

## 4. 用户可以做什么

1. 打开本机或 Tailscale `/api-key`，点击“查看/刷新用量”。按钮只读统计，不调用模型；空历史正常。
2. 正常使用聊天、任务、学习或娱乐后再次刷新，观察记录数、已知用量和缓存统计覆盖率。不要把缺失 usage 当作免费，也不要把部分已知费用当作完整账单。
3. 如需费用估算，按实际 Provider/Model 官方报价配置服务端 `AI_TOKEN_PRICES_JSON` 并重启 Web/Worker；未配置价格时显示未知。格式见配置指南，示例数字不是官方报价。
4. APK 如需新增用量 UI，覆盖安装本轮 Debug 包；后端预算与用量采集已经在 Docker 生效。

## 5. R1 后续及封版条件

- 先用正常使用数据建立冷/热请求、短/长对话、历史分支、联网、任务、学习、娱乐场景基线。额外收费对照需先明确模型价格与总费用上限，再核验回答质量和真实费用，不只比较命中率。
- 长聊天仍发送完整所选分支。下一轮设计可回退的“摘要 + 近期窗口”，定义覆盖节点/内容哈希、模型与策略版本、Persona/记忆变化失效、分支/删除隔离及失败回退；摘要自己的调用也计费，净收益与质量通过后才默认启用。
- 精确分词与额外应用检索缓存由真实数据决定优先级；不缓存整段个性化回答，不为提高命中添加无用内容或收费预热。
- 以上验收完成后再标记 R1 封版；R2 UI 优化仍未开始，移动/语音真机清单、Phase 5.6 和 Phase 8 保留原顺序。
