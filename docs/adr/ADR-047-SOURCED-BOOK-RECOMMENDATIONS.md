# ADR-047：书籍推荐使用显式阅读画像与检索证据

- 状态：Accepted
- 日期：2026-09-27
- 对应阶段：Phase 4.3

## 背景

个人简报已经验证 Scheduler → Worker → Web Search → Model → Inbox → Push 的主动内容链路。书籍推荐需要复用这条链路，但推荐质量还取决于用户读过什么、想读什么、排斥什么、当前难度、阅读目标和时间预算。把这些信息塞进聊天长期记忆会缺少可见性和可修改性；建立通用推荐平台、向量画像或行为评分又超过当前单用户项目所需范围。

## 决策

1. 新增一对一 `reading_profiles`，只保存用户显式填写的主题、已读/想读/不喜欢书单、难度、目标和每周分钟数，使用版本号处理多端并发修改。
2. 新增 `book_recommendation` Task/Inbox 类型，继续复用现有调度租约、失败语义、持久收件箱和通知投递，不建立第二套定时系统。
3. Worker 先读取阅读画像，再检索书目网页；模型只能推荐检索证据能够确认书名、作者和基本信息的书，每本书都必须引用已知来源编号。
4. 输出固定为“本次推荐、为什么现在推荐、阅读门槛与投入、试读与判断”四段，系统代码附加真实链接和画像摘要。推荐 2–3 本，禁止长篇摘录、编造章节、ISBN、版本或阅读体验。
5. 用户通过独立 `/reading` 页面修改画像；书籍结果在 Inbox 提供画像和任务设置入口。当前不根据单次点击自动改写长期偏好。

## 未选择的方案

- 不从聊天记录隐式推断画像：难以纠错，也容易把临时讨论误当长期偏好。
- 不建立通用 ContentItem、Embedding 或推荐排序服务：目前只有两个主动内容消费者，实际数据量不足以证明额外复杂度。
- 不抓取或保存图书全文：书目信息和必要摘要足以支持当前推荐，保存全文会增加版权、存储与提示注入风险。
- 不把模型自由输出直接当作书目事实：链接和来源清单由代码根据检索结果附加，未知引用会使本次运行失败。

## 后果与回滚

阅读画像具备明确的用户控制和服务端持久性，书籍推荐也拥有可核查来源；代价是首次使用前需要用户填写少量信息，且搜索质量会影响可推荐书目。迁移 `0014_hot_bromley` 可回滚：已有 `book_recommendation` Task 与 Inbox 来源降级为 `agent_prompt` 以保留主题和正文，随后删除阅读画像表并恢复旧约束。
