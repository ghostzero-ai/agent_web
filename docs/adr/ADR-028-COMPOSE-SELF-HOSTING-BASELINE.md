# ADR-028 使用 Docker Compose 建立单用户自托管基线

## 状态

Accepted

## 背景

个人用户希望让笔记本承担服务端，并在未来方便迁移到云端。只运行 `npm run dev` 无法提供稳定进程、持久数据库、健康依赖、自动迁移与可重复备份；直接采用云厂商专有服务又会过早绑定部署平台。

## 决策

- 使用 Docker Compose 组合单个 Next.js Web/API 容器与 PostgreSQL 容器。
- PostgreSQL 只在 Compose 私有网络提供服务，不映射宿主机端口，并使用命名卷持久化。
- Web 默认只绑定宿主机 `127.0.0.1`，局域网暴露必须显式配置。
- Web 等待数据库健康，入口脚本先运行版本化迁移，再启动生产服务器。
- 健康端点以数据库为 readiness 必要条件，模型未配置只标记 degraded。
- 提供 PowerShell 与 POSIX Shell 的 `pg_dump`/`psql` 备份恢复脚本；恢复必须显式确认并失败即停。
- 密钥只由未提交的环境文件或未来云 Secrets 注入，不写入镜像。

## 备选方案

### 直接在宿主机安装 Node.js 与 PostgreSQL 服务

资源更少，但重装、升级、备份和云迁移更依赖机器状态，不利于作品集复现。

### 立即使用 Kubernetes

对单用户双容器应用没有收益，运维与安全面显著扩大。

### 只部署到 Vercel 和托管数据库

适合公开 Web，但不能直接满足用户的笔记本自托管学习目标，也会提前产生平台依赖。

## 后果

- 本机与云端共享镜像、环境变量和数据库迁移模型。
- 笔记本休眠、关机或 Docker 未启动时仍不可用；`restart` 不是高可用。
- 当前镜像为保证启动时运行 TypeScript 迁移脚本而保留完整 node_modules，后续可在部署稳定后优化镜像体积。
- 首次容器运行和备份还原仍必须在安装 Docker 的环境进行实机演练。
