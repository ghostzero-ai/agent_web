# ADR-039：Android 本地通知离线恢复与系统边界

- 状态：Accepted
- 日期：2026-09-26

## 背景

M0.4 已能把任务同步为 Capacitor Local Notifications，但应用启动或恢复时仍依赖服务端重新读取任务。手机暂时无法连接笔记本时，现有原生闹钟不会因此消失，但精确闹钟权限变化、应用更新或系统重排后缺少可靠的离线恢复来源。华为系统的“从最近任务划掉”和“强行停止”也必须明确区分：前者不应影响系统闹钟，后者会冻结应用、闹钟和广播，普通 APK 无法绕过。

## 决策

1. 每次从服务端成功同步任务并完成原生调度后，在 Capacitor Preferences 保存一份最小 `LocalReminderSnapshot[]`。缓存只包含任务 ID、Occurrence ID、标题、提醒时间、重复规则和应用内深链，不保存任务 Prompt、API Key 或数据库信息。
2. APK 启动和回到前台时优先读取服务端；若服务端不可达，则使用最后一次通过校验的设备快照执行 reconcile。损坏、超量或含非法深链的缓存直接丢弃，不进入原生调度。
3. 服务端仍是任务事实源，设备缓存只用于离线恢复。在线同步成功后立即覆盖缓存；暂停或删除任务会在下一次在线同步时取消旧提醒。
4. 在 Android Manifest 中向 Capacitor 的 `LocalNotificationRestoreReceiver` 合并 `TIME_SET`、`TIMEZONE_CHANGED` 和 `MY_PACKAGE_REPLACED`，补充插件已有的开机恢复。
5. 通知设置页展示同步来源和缓存时间；精确闹钟未允许时提供系统设置入口。关闭精确闹钟后 Android 可能删除原闹钟，应用恢复时会从服务端或设备缓存重新调度。
6. 不申请绕过电池优化的特殊权限，也不伪装常驻服务。界面明确提示用户在华为系统中允许自启动和后台活动；系统“强行停止”后必须由用户重新打开应用。

## 后果

- 笔记本关机或 Tailscale 暂时不可用时，已同步提醒仍可由设备缓存修复和继续调度。
- 设备快照可能短暂落后于服务端，因此离线期间不允许把它视为任务事实源；界面必须显示“设备离线缓存”。
- Android 原生广播可以覆盖重启、手动校时、时区变化和应用覆盖安装，但无法覆盖厂商强制停止语义。
- 断网、重启、省电和系统清理仍必须通过真实华为设备验证，自动化测试只能覆盖调度输入、缓存回退和 Manifest 产物。
