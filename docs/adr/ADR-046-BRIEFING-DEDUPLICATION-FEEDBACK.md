# ADR-046：个人简报使用确定性跨期去重与轻量反馈

- 状态：Accepted
- 日期：2026-09-27
- 对应阶段：Phase 4.2

## 背景

Phase 4.1 能按计划生成有来源的个人简报，但每日搜索可能返回同一事件的原链接、转载或轻微改写标题。直接把所有结果交给模型会重复消耗额度，并让 Inbox 反复推送相同内容。当前是单用户个人项目，尚没有足够反馈数据支撑向量检索、兴趣画像或通用推荐平台。

## 决策

只在个人简报垂直切片中保存模型实际引用来源的公开签名：标题、原 URL、站点、发布日期、规范 URL 与规范标题。下一次执行时读取同一 Task 最近 30 天的签名，并在模型调用前完成两层过滤：

1. 本次搜索结果内部先聚类，避免同一事件的多篇转载占据简报。
2. 与历史签名比较；规范 URL 或规范标题相同即视为重复，否则使用 Unicode 规范化标题的字符二元组 Dice 相似度判断近似事件。

默认阈值较保守。用户把历史简报标为“不相关”或“内容重复”后，该简报内来源使用更严格的阈值，以减少类似主题再次出现。“有帮助”只记录正反馈，不突破 30 天重复抑制。反馈不会自动修改用户填写的主题。

若搜索结果全部被过滤，Worker 把 Run 标为 `skipped`；不调用模型、不创建 InboxItem、不触发 Push，也不把正常的“暂无新进展”记录为系统失败。

## 数据与 API

- `inbox_items.briefing_sources` 保存实际引用来源签名，仅允许个人简报写入。
- `inbox_items.feedback` 允许 `helpful`、`not_relevant`、`duplicate` 或 null，仅允许个人简报写入。
- `PATCH /api/v1/inbox/:id` 继续处理已读状态，并增加一次只更新一个反馈字段的严格请求形状。
- Inbox 提供反馈按钮与任务深链；任务页通过 `task` 和 `edit=1` 参数进入对应任务编辑状态。

## 放弃的方案

- 不使用正文字符串比较：Markdown、日期和措辞变化会造成不稳定结果。
- 不使用向量数据库：当前数据量和单用户需求不足以覆盖额外部署、迁移与可解释性成本。
- 不让模型自行判断历史重复：会增加一次调用、成本和随机性，而且无法在模型调用前节省额度。
- 不建立通用 ContentItem/EventCluster 表：Phase 4.2 只有一个真实消费者，过早抽象会偏离产品主线。

## 后果与边界

该方案对同 URL、转载和近似标题可解释且容易测试，但跨语言标题、完全不同标题描述的同一事件可能漏判。若 Phase 4.3–4.4 出现第二个真实内容消费者，再根据实际数据考虑独立事件表或语义向量；在此之前保持 JSONB 签名和模块化单体。

迁移 `0013_aspiring_maximus` 可回滚；回滚只删除签名和反馈字段，保留 Inbox 正文、任务和 Run 历史。
