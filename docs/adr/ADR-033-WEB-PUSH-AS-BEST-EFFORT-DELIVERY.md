# ADR-033：Web Push 作为可失败投递渠道

- 状态：Accepted
- 日期：2026-09-12

## 背景

Sprint 2.3 已把提醒可靠地写入 Durable Inbox，但用户必须主动打开页面。浏览器 Push 可以在网页关闭时显示系统通知，不过权限、Push Service、操作系统策略和电脑在线状态都不受应用完全控制，不能承担唯一事实来源。

## 决策

1. InboxItem 继续作为提醒事实；Web Push 只是从 Inbox 派生的 best-effort Delivery。
2. 每个 InboxItem 与 PushSubscription 最多一条持久投递，使用唯一约束、数据库行锁、租约和 attempt fencing 防重复完成。
3. VAPID 密钥首次使用时生成并稳定保存；私钥和完整订阅使用现有主密钥 AES-256-GCM 加密，并用不同 AAD 隔离用途。
4. 权限只在用户点击启用后申请。全局开关默认关闭，安静时段默认北京时间 22:00–08:00，并在规划和实际发送前各检查一次。
5. 锁屏载荷只包含通用文案与 InboxItem ID，任务标题、正文和 prompt 留在受保护的应用页面。
6. 临时错误指数退避且最多尝试 5 次；404/410 将设备订阅标为失效并取消其余投递。
7. 新设备不补推订阅之前的历史 InboxItem，避免首次启用形成通知风暴。

## 取舍

- 不引入 Redis/BullMQ：当前单用户规模使用 PostgreSQL 已能保证持久性与并发安全，减少额外服务和运维成本。
- 不承诺 exactly-once 系统通知：外部 Push Service 与操作系统可能延迟、聚合或重复，用户应以 Inbox 为准。
- 固定 Asia/Shanghai 简化首版时区边界；多用户与旅行场景需要把时区提升为用户偏好并定义变更语义。
- 通用锁屏文案牺牲了一步可读性，换取锁屏隐私；点击后才能在应用内读取具体内容。

## 结果

网页关闭后，只要笔记本、Docker Worker 与网络保持运行，任务到期会先可靠写入 Inbox，再尝试向已授权设备发送系统通知。失败投递可在重启后恢复，失效设备可自动隔离，且不影响 Inbox 中的提醒事实。
