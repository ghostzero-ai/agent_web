# ADR-052：设备系统 TTS 作为可失败输出层

- 状态：Accepted
- 日期：2026-09-27
- 对应：Phase 5.4

## 背景

项目希望助手能够说话并允许用户选择音线，但 DeepSeek 等当前文本模型不提供本项目可直接依赖的语音接口；贸然绑定商业 TTS 会提前引入费用、凭据、配额、音频缓存与声音授权问题。语音也不能反过来决定模型答案或让播放故障破坏已生成文字。

## 决策

1. 文字回答是唯一事实来源。TTS 在回答完成后由用户手动触发，读取失败、设备不支持或播放失败只产生局部 UI 错误。
2. 首个 Provider 使用浏览器/Android WebView 提供的 Web Speech 系统语音。它免费、无需新凭据且不向额外 TTS 服务上传正文，但音线集合由当前设备决定。
3. `voice_profiles` 只保存 `system` Provider、voice ID、语言、语速、音高、音量与版本；voice ID 在新设备不存在时按完整语言、基础语言、默认音线的顺序回退。
4. 所有播放通过 `SpeechOutputAdapter`。组件不直接操作 `speechSynthesis`，未来 Capacitor 原生、ArkTS 或服务端 Provider 可替换实现而不改聊天领域逻辑。
5. Speech Policy 在本地移除 URL 与 Markdown 装饰，把公式替换为提示并省略代码块；单次最多 5000 字符、按句分块、可随时停止。
6. 不提供自动播放、真人声音克隆或冒充模板。系统语音没有统一情绪接口，因此本阶段不保存虚假的情绪强度。
7. 未来服务端 Provider 必须独立实现凭据保管、明确费用/额度、字符上限、可删除缓存 TTL 与声音授权；不得改变文字回答成功语义。

## 结果

- Web 与本地打包 APK 共享 Voice Profile UI 与播放策略，不维护第二套业务代码。
- 用户可试听、停止和切换当前设备音线，并从聊天消息手动朗读；换设备可能听到不同音线，但设置会按语言安全降级。
- 当前不生成音频文件，因此没有 Audio Cache；真实华为卓易通/WebView 的系统语音支持仍属于人工真机验收项。

## 回滚

迁移 `0019_voice_profile` 的回滚会删除 `voice_profiles`。代码回退后聊天文字和模型调用不受影响，只移除语音设置与朗读入口。
