# ADR-056：背书活动必须通过 Capability Gateway 形成闭环

- 状态：Accepted
- 日期：2026-09-29
- 阶段：Phase 7.3

## 决策

背书训练作为第一方 Activity 插件交付，但不直接取得数据库、模型配置或 Task Repository：

1. 材料、知识单元、成绩与薄弱点写入 `storage.read-write` 的插件隔离空间。
2. 复述先经过可测试的确定性双字组评分；获得 `model.generate` 授权时，再由宿主受控模型 Adapter 给出语义评价并混合评分。模型不可用时活动仍可继续。
3. 间隔天数由确定性规则计算：低于 60 分为 1 天、60–79 分为 3 天、80–89 分为 7 天、90 分以上为 14 天。
4. `task.create-draft` 只返回经过宿主校验的单次提醒草稿。插件不能创建任务；用户点击确认后，客户端才调用核心 Task API。
5. Capability 审计只记录操作名、结果、配额和耗时，不记录学习材料、复述、模型反馈或任务正文。

## 原因

Phase 7 的目标不是做一个只能展示 Manifest 的插件目录，而是用真实活动验证边界。背书闭环同时需要私有状态、模型计算和核心写入请求，足以暴露 Gateway 输入 Schema、失败降级、授权与确认边界中的问题。

## 后果

- 禁用插件或撤销存储授权后，活动数据仍保留但不可访问；核心聊天和任务不受影响。
- 未授权模型时使用确定性评分；未授权任务草稿时保存学习记录但不提供提醒草稿。
- 当前第一方 UI 与宿主同包，并不构成第三方 UI 沙箱。Plugin API 仍保持实验版，待 7.4 解题插件复用后再冻结。
