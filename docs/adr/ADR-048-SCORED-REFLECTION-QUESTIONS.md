# ADR-048：思考问题采用共享候选池与确定性评分

- 状态：Accepted
- 日期：2026-09-27
- 对应阶段：Phase 4.4

## 背景

Phase 4.1 的个人简报要求模型直接输出一个问题，形式合规但无法稳定保证相关性、新颖性和节制性，也无法避免跨期重复。项目还需要独立的每周复盘任务；若两者各自维护 Prompt 和规则，会很快产生不同的质量标准。当前单用户规模不需要通用评测平台或第二模型裁判，但需要可解释、可测试和可关闭的最小闭环。

## 决策

1. 个人简报和 `reflection_question` 定时任务共用 `ReflectionQuestionGenerator`。普通聊天不自动附加问题，避免破坏专业回答的完整性。
2. 模型只生成 3–5 个严格 JSON 候选，标注问题类型、价值说明与 1–5 级情绪负担；代码不信任该排序。
3. 代码先过滤空泛问题、是非式开头、用户避开话题、温和模式下的高负担问题，以及与 90 天历史高度相似的问题，再按相关性 35%、新颖性 25%、可行动性 25%、低情绪负担 15% 评分。
4. 默认交付最高分的 1 个，可由用户设置为最多 1–3 个；多问题必须类型不同且彼此不近似。Inbox 保存最终问题和各项分数，便于解释和后续调优。
5. `reflection_preferences` 只保存用户显式填写的目标、避开话题、风格、数量和开关，并使用版本号防止多端覆盖。关闭后独立任务跳过，个人简报降级为无问题版本。
6. 非法模型结构或全部候选不合格时不交付低质量问题。个人简报对此做非阻断降级；独立反思任务记录终态失败，配置/历史读取等暂时错误则保留重试语义。

## 未选择的方案

- 不让模型直接自选“最佳问题”：不可稳定复现，也无法执行硬性的避开话题与历史去重。
- 不调用第二个模型评分：会增加延迟、费用和新的不确定性，当前启发式已能满足“少而精”的验收目标。
- 不读取聊天记录推断情绪、人格或长期目标：Phase 5 的确认式记忆尚未建立，隐式推断缺少纠错入口。
- 不建立通用 Evaluation Service：目前只有两个真实消费者，共享模块足够，继续抽象会偏离产品主线。

## 后果与回滚

每份问题都具有可查看的选择依据，两个触发入口保持同一标准；代价是个人简报启用问题时会增加一次模型调用，启发式相关性对同义改写仍可能误判。迁移 `0015_parched_pyro` 可回滚：独立反思任务和 Inbox 来源降级为 `agent_prompt` 以保留主题和正文，然后删除评分 JSONB 与偏好表。
