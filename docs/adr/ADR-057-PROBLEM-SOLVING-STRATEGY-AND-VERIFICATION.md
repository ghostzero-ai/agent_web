# ADR-057：解题策略、图片边界与工具核验

- 状态：Accepted
- 日期：2026-09-29
- 阶段：Phase 7.4

## 决策

1. 解题活动只提供四种显式策略：先给提示、逐步引导、检查答案、完整讲解。策略作为 `model.generate` 的结构化枚举传入，不能由题目文本或自由标签切换。
2. 文字题直接进入受控模型 Adapter；图片在客户端缩放至最长边 1600 像素并压缩，单次请求最多 4 MB。原图不写入数据库，只保存名称、MIME、大小与模型提取后的自包含题意。
3. 宿主在调用模型前用无 `eval` 的算术解析器核验基础四则运算，并把结果作为不可被题目覆盖的工具证据。无法适用时明确显示“未做确定性工具核验”，不把模型判断伪装为工具结论。
4. 每轮保存策略、用户答案、模型反馈、判断、错因标签、下一步问题、工具证据与模型名；最多保留 30 轮。
5. 复习卡必须由用户主动请求，再通过受控模型生成并写入解题插件的隔离存储。任务能力仍只产生草稿，用户再次确认后才进入核心 Task API。
6. 解题插件从基础状态升级为 `0.2.0`；旧安装必须审核更新，旧版本能力授权必须重新确认。

## 原因

默认直接给完整答案会削弱学习过程，也无法验证 Plugin API 是否能承载多轮活动。图片和模型结论又具有不同的隐私与可靠性风险，因此必须把策略、短暂图片传输、持久化数据和确定性核验分开。

## 后果

- 非基础算术题当前只有模型分析，不声称已由计算器、CAS、代码沙箱或检索工具验证。
- 图片题首次成功分析后可以依靠提取后的题意继续；若首次请求失败且用户离开页面，需要重新选择原图。
- 复习卡当前属于解题插件记录，不直接写入背书插件；跨插件卡片能力留给 Phase 7.5 的 API 复盘决定。
