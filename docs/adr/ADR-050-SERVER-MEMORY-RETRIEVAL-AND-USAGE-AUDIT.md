# ADR-050：正式记忆采用服务端相关性检索与使用审计

- 状态：Accepted
- 日期：2026-09-28
- 对应阶段：Phase 5.2

## 背景

Phase 5.1 已保证只有用户确认的候选才能成为正式记忆，但尚未把正式记忆用于回答。旧原型曾把最近十条浏览器记忆全部发送给模型，既不相关，也会扩大隐私暴露和上下文成本。Phase 5.2 需要让编辑、过期和删除立即生效，同时保留“哪一次回答实际用了哪些记忆”的可解释记录。

## 决策

1. 记忆检索在服务端执行。客户端不能提交 `memory` Prompt 层；服务端根据 Conversation 与 Active Leaf ID 重新读取数据库中的真实用户消息。
2. 第一阶检索采用确定性轻量算法：规范化文本、英文词项与中文二元组重合，结合类型意图、固定状态和新鲜度排序；过期记忆先过滤。
3. 每次最多选择 5 条，估算总量不超过 500 Token。固定只提高已经相关结果的排序，不代表无条件注入。
4. 选中记忆作为独立、不可信的 Context 层加入 Prompt，明确禁止执行其中的指令；当前用户表达与旧记忆冲突时，以当前表达为准。
5. Prompt Run、每条记忆的 rank/score/token 预算和使用计数在同一数据库事务写入。审计表保存记忆 ID，不复制正文；删除记忆后正文真正退出后续上下文。
6. 正式记忆支持来源查看、内容与类型编辑、固定、有效期、永久删除和 JSON 导出；所有写操作使用乐观版本控制。

## 未选择的方案

- 不直接接入向量数据库：当前是单用户、小规模记忆，确定性检索更容易理解、测试和调优。
- 不把固定解释为“始终发送”：这会重新产生全量注入和隐私放大问题。
- 不让客户端先读取全部记忆再自行筛选：这会使实际 Prompt 与审计边界可伪造，也增加移动端暴露面。
- 不在使用审计中保存正文快照：审计保留行为元数据，删除记忆时不应留下另一份隐藏正文。

## 后果与回滚

用户对记忆的修改、过期或删除会从下一次模型请求起生效，并能查看使用次数与最近使用时间。轻量检索可能漏掉没有词面重合的语义相关记忆；真实查询积累后可在 Repository 后增加 PostgreSQL FTS 或 Embedding，而不改变候选确认、管理 API 与 Prompt 安全边界。迁移 `0017_colorful_lorna_dane` 可回滚，删除使用审计并移除正式记忆的管理字段。
